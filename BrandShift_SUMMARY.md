# BrandShift — Project Summary

A reference document describing the full state of the BrandShift codebase. Generated by reading the actual source files; every claim below points back to a path in the repo.

---

## 1. Project Overview

**BrandShift** is an AI-powered brand intelligence platform built for Indian consumer brands (D2C, FMCG, fashion, tech, B2B). It turns a brand's public footprint into a structured audit, a multi-month action plan, and an ongoing operating dashboard.

**Who it's for:**
- D2C founders and brand managers in the Indian market
- Agencies running audits for client brands (the `agency` plan exists in `accounts.plan`)
- Marketers who want a single weekly source of truth: where the brand stands, what to do next, what content to make

**What the user actually does:**
1. Fills a 5-step audit wizard with brand info, website, Instagram, LinkedIn, competitors
2. Watches a live "scrape → analyse → score" pipeline run in the loading screen
3. Receives a Brand Relevance Score (0-100) broken into 5 dimensions, with quoted evidence
4. Sets direction + tone, gets an 8-week prioritised roadmap
5. Returns daily to a dashboard with today's task, streak, score history, Monday brief, content idea, trend fit, voice check, pre-flight campaign check, and a "Brand Constitution" wizard
6. Optionally shares a public report or sends a cold-outreach email about another brand's audit

The product positions itself with the tagline "Know exactly where your brand stands" ([app/layout.js:42-51](app/layout.js#L42-L51)). The scoring is anchored to two academic frameworks: Ehrenberg-Bass Brand Salience and Keller Brand Resonance ([lib/prompts.js:1-30](lib/prompts.js#L1-L30)).

- `@lottiefiles/react-lottie-player` for dashboard animations
- `node-vibrant` for extracting brand colour from favicon ([app/api/tools/extract-color/route.js](app/api/tools/extract-color/route.js))

**Analytics**
- PostHog via [lib/analytics.js](lib/analytics.js) — `trackEvent`, `trackPageView`, `identifyUser`. Disabled if `NEXT_PUBLIC_POSTHOG_KEY` is missing.

**Misc**
- Pure-JS semantic similarity engine in [lib/semanticSimilarity.js](lib/semanticSimilarity.js) (synonym dictionary + n-gram overlap) — used by the pre-flight check. Originally `@xenova/transformers`, ripped out for Vercel build compatibility per git history.

**Hosting**
- Vercel ([vercel.json](vercel.json)): default function `maxDuration: 60s`, Monday-brief cron `300s`, cron `schedule: "0 18 * * 0"` (Sunday 18:00 UTC).
- Custom domain `brandshift.in` per [README.md](README.md). Current Vercel URL: `https://brand-shift-tpea.vercel.app`.

### End-to-end audit data flow

1. **`/audit`** — user fills `formData` (brandName, industry, targetAudience, websiteUrl, instagramHandle, linkedinPage, comp1/2/3, challenge). On submit, saved as JSON to `localStorage.brandshift_intake` and routed to `/loading` ([app/audit/page.js:180-192](app/audit/page.js#L180-L192)).
2. **`/loading`** — reads intake from localStorage, POSTs `/api/scrape`. The scrape route hits homepage first (so its content fingerprint can be reused to detect duplicate About/Blog pages), then in parallel: about, blog, Instagram (Apify), LinkedIn (Apify with Firecrawl fallback), comp1, comp2 ([app/api/scrape/route.js:303-380](app/api/scrape/route.js#L303-L380)). Each scrape is wrapped in `withTimeout`. Instagram captions are then summarised by a small Claude call (`extractInstagramSignals`). The full scrape result is POSTed to `/api/score`.
3. **`/api/score`** — fills `SCORING_USER_PROMPT` template, calls Claude with `SCORING_SYSTEM_PROMPT`, extracts JSON, scores the competitor as a second small Claude call, saves a row to `brand_audits` plus appends to `brand_profiles.score_history` ([app/api/score/route.js:56-180](app/api/score/route.js#L56-L180)). The score is returned and saved to `localStorage.brandshift_score`.
4. **`/results`** — reads score from localStorage, renders animated score ring, radar chart, dimension breakdown, evidence tabs (Website / Instagram / LinkedIn conditional / Competitors), Keller maturity path, score-simulation insight ("fixing your top 2 gaps could push your score from 61 to 68"). CTA → `/roadmap` setup.
5. **`/roadmap`** — collects direction + tone, calls `/api/roadmap`. The route fills `ROADMAP_PROMPT`, parses the JSON `two_months/six_months/one_year/bigger_picture` structure, flattens the 2-month actions into `tasks[]` via `flattenRoadmapToTasks` ([lib/helpers.js](lib/helpers.js)), saves `current_roadmap` + `tasks` + `current_week=1` to `brand_profiles`.
6. **`/dashboard`** — `useDashboard()` resolves the brand (account → localStorage fallback), fetches `/api/profile`, derives all UI state: `todayTask`, `streak`, `latestScore`, `scoreDelta`, `constitutionProgress`, `latestBrief`, `contentIdea`, `trends`, `voiceCheckUsage`.

### Routing rules (post-auth)

All routing decisions go through a single helper: [`lib/postLoginRoute.js`](lib/postLoginRoute.js) → `getPostLoginDestination(account, profile)`.

```
no account.primary_brand          → /audit
account.primary_brand, no roadmap → /results  (user generates roadmap from there)
account.primary_brand + roadmap   → /dashboard
```

Callers:
- [`app/auth/callback/route.js`](app/auth/callback/route.js) — after OAuth/magic-link, claims the most recent unowned `brand_profile` if needed, then calls `getPostLoginDestination` with the freshly-fetched `account` + `profile.current_roadmap`.
- [`app/login/page.js`](app/login/page.js) — email-password submit fetches `/api/auth/account` + `/api/profile`, calls the helper, redirects.
- [`app/page.js`](app/page.js) — landing-page "Go to Dashboard" button uses the helper. The auto-redirect path for already-signed-in visitors now makes a single API call (`/api/auth/account`) and delegates further routing to `/dashboard` (which already redirects to `/results` if there's no roadmap). The earlier two-call version caused a multi-second flash of the landing page.
- [`app/(dashboard)/dashboard/page.js`](app/(dashboard)/dashboard/page.js) — guard for users with no roadmap routes to `/results` (where they can generate one), not the bare `/roadmap` view.

### Landing-page bounce protection (commit `ebd052d`)

Two-layer guard so logged-in users never see the marketing page between login and dashboard:

1. **Server-side** — [middleware.js](middleware.js) now redirects authenticated users from `/` to `/dashboard` (previously only `/login` and `/signup` were redirected). This is the fastest path and runs before any HTML is rendered.
2. **Client-side splash** — [app/page.js](app/page.js) synchronously detects auth-in-flight signals on first render and shows a logo + spinner instead of the full landing UI:
   - URL hash containing `access_token`, `refresh_token`, or `error_description` (Supabase implicit-flow fallback)
   - URL query containing `?code=…` (PKCE callback that mis-landed on `/`)
   - A live `sb-*-auth-token` cookie (logged-in user with hot cache)

   If `getSession()` later reveals no real session (stale cookies), the splash flips back to the landing page so organic visitors aren't stuck.

**Supabase Dashboard reminder**: `https://<vercel-domain>/auth/callback` and `http://localhost:3000/auth/callback` must be added to Authentication → URL Configuration → Redirect URLs. Without them, OAuth falls back to Site URL (`/`) and round-trips through the splash unnecessarily — the code handles it gracefully but it's wasted work.

Middleware also still protects `/dashboard`, `/roadmap`, `/preflight`, `/constitution`, `/outreach`, `/reports`, `/settings` (redirects unauthenticated → `/login?redirect=…`).

### Claude usage pattern

All Claude calls go through [lib/claudeClient.js](lib/claudeClient.js):
- `callClaude(params, maxRetries=3)` — retries on 429 / 529 with linear backoff (3s, 6s, 9s)
- `extractJSON(rawText)` — tries direct parse → JSON object match → JSON array match → fix-and-retry (strip trailing commas, single quotes, control chars)
- `callClaudeJSON(params, maxAttempts=3)` — wraps both above for routes that need structured output

The scoring and roadmap routes use their own ad-hoc `extractJSON` (older code, not yet migrated to the shared helper).

## 5. Features Implemented

### 5.1 Audit pipeline
- 5-step wizard with industry/audience auto-suggest ([components/SuggestInput.js](components/SuggestInput.js)), URL normalisation, `@` strip for Instagram handles, optional LinkedIn URL, 1-3 competitors, brand challenge free text. ([app/audit/page.js](app/audit/page.js))
- Live loading page with terminal-style progress lines, fixed activity feed on the right, gradient progress bar. ([app/loading/page.js](app/loading/page.js))
- Parallel scraping (homepage → about/blog/Instagram/LinkedIn/comps) with timeout fallbacks and content-fingerprint dedup so the About page isn't scraped twice. ([app/api/scrape/route.js](app/api/scrape/route.js))
- Claude scoring against 5 dimensions (Visual Identity 25%, Brand Voice 25%, Trend Relevance 20%, Competitor Positioning 20%, Audience Alignment 10%). Each dimension carries `score`, `framework`, `justification`, `evidence_quote`, `improvement_action`, plus per-dimension extras (`distinctive_assets_found`, `voice_in_3_words`, `entry_points_found`, `positioning_gap`, `resonance_level`). ([lib/prompts.js:160-390](lib/prompts.js#L160-L390))
- Channel-weight detection: scorer auto-classifies brand as SOCIAL-FIRST / CONTENT-FIRST / LINKEDIN-PRIMARY / BALANCED and adjusts dimension weighting accordingly.
- Data-confidence band (HIGH / MEDIUM / LOW) emitted in the score JSON; surfaced in the results UI as a dot scale + source pills.
- Evidence quotes tagged with positive/negative sentiment via keyword scan in [app/api/score/route.js:23-39](app/api/score/route.js#L23-L39).
- Competitor dimension scoring as a separate, low-cost Claude call (`max_tokens: 300`) for radar-chart overlay. ([app/api/score/route.js:137-173](app/api/score/route.js#L137-L173))

### 5.2 Results page

**Section order** (top to bottom):
1. Fixed top bar (Logo · Back to audit · Share Report · Generate Roadmap)
2. **Evidence Teaser strip** — full-width horizontal-scroll pills below the top bar
3. Score hero (ring + verdict + badges)
4. Score Simulation + Brand Maturity Path
5. Radar + Dimensions
6. Key Findings (Strength + Gap)
7. Full Evidence section (tabs)
8. CTA "Ready to close the gaps?" (`id="roadmap-cta"`)

**Evidence Teaser** ([app/results/page.js:171-329](app/results/page.js)) — `EvidenceTeaser` component:
- Renders up to 6 pills in priority order: homepage screenshot, first Instagram caption, first positive evidence quote, first negative evidence quote, competitor quote, brand-voice quote. Each pill is skipped if its source data is missing.
- Pill border colour is sentiment-coded: positive = teal, negative = orange, screenshot/voice/competitor = violet.
- Helper text above strip: "Here's what we found on your brand →".
- Pills are horizontally scrollable (no visible scrollbar — `::-webkit-scrollbar { display: none }` + `scrollbarWidth: none`).
- Click any pill → smooth-scrolls to `#full-evidence`.
- Strip has `padding-top: 72px` to clear the fixed top bar (56px + breathing room).

**Other sections**:
- Animated SVG score ring with counter (1.5s ease-out).
- "What if you fixed your top 2 gaps?" simulation card — projects bottom-2 dimensions to score ≥70 and recomputes the weighted average.
- Radar chart with brand + competitor overlay ([components/BrandRadarChart.js](components/BrandRadarChart.js)).
- 2×2 metric grid: Brand Maturity (Keller level), Primary Channel (detected brand type), Instagram Signal, Sources Analysed.
- Evidence tabs — Website / Instagram / LinkedIn (only when scraped) / Competitors. ([components/EvidenceSection.js](components/EvidenceSection.js))
- "What we analysed" collapsible source list and Keller maturity-path visual.

**Generate Roadmap CTA (auth wall + return flow)**:
- If user is **not** signed in: `handleRoadmapCta` saves `{returnTo: '/results', action: 'generate_roadmap', brandName, savedAt}` to `localStorage.brandshift_preflight_return` and pushes `/login?redirect=/results&action=generate_roadmap`.
- After login, user returns to `/results?action=generate_roadmap` — a `useEffect` reads the saved return state, validates `savedAt` is within 10 minutes, clears the storage key, shows a violet "Welcome back — you're signed in. Ready to generate your roadmap ↓" banner (`position: fixed; top: 70`), and smooth-scrolls to `#roadmap-cta`. Banner auto-hides after 6s.

### 5.3 Roadmap
- Direction + tone-direction picker → `/api/roadmap` ([app/api/roadmap/route.js](app/api/roadmap/route.js)) returns `two_months.actions[]`, `six_months.milestones[]`, `one_year.objectives[]`, `bigger_picture.{vision, market_position}`
- 8-week actions get flattened into `brand_profiles.tasks[]` with `id`, `week`, `task`, `effort`, `why`, `status='todo'`, `exit_interview: null`
- Roadmap is cached to `localStorage.brandshift_roadmap` and `brandshift_roadmap_brand` for offline/return access
- Path visualisation ([components/RoadmapPath.js](components/RoadmapPath.js))

### 5.4 Dashboard

**Today's Focus card** — primary visual hierarchy, dominates the screen:
- Padding 32×36, full-card gradient background (`linear-gradient(135deg, rgba(232,98,42,0.08) 0%, var(--bs-card-dark) 60%)`), violet-orange tinted border. No left orange border (replaced).
- Decorative `W{currentWeek}` watermark — JetBrains Mono 96px, opacity-4% orange, absolute positioned right-32 / vertically-centered.
- Section label format: `TODAY'S FOCUS · {weekday}, {day} {month}` (e.g. "TODAY'S FOCUS · Monday, 12 May").
- Task font size: 18px (was 15px), no max-width — fills the card.
- Week progress line below the task meta: "Week N progress" + "{done}/{total} tasks" + animated bar (orange while in progress, teal when 100%). Counts ALL tasks for the week, not the 3-visible slice.
- Streak: "{N} day streak" 🔥 when `pulse_streak > 0`, "Complete a task to start your streak" otherwise.
- "Mark done →" opens the exit-interview modal.

**Exit interview modal (`ExitModal`)** — opens on "Mark done →":
- Form: pill row (Yes ✓ / Partially / Not yet) + "What happened?" textarea + "What would you do differently?" textarea.
- Save persists via `markTaskDone` → `/api/tasks/complete` → updates `tasks[i]`, recomputes `pulse_streak`, writes `task_history`.
- After save, the modal switches into a success view (does NOT auto-close) showing a teal "Task complete ✓" card with `getTaskImpactMessage(task, profile)`:
  - Finds the user's weakest dimension from `latest score_history[-1].dimensions`.
  - "This task directly targets your {DimensionName} score ({N}/100) — your biggest gap. {done} of {total} tasks done this week."
  - When all this-week's tasks done: "You've completed all tasks for Week {N}. Your score refreshes Monday — keep going."
- User clicks "Done" to close.

**Other dashboard pieces (secondary information panels — `.card` padding 20px)**:
- Greeting + date.
- Score card with mini ring, score delta vs previous entry, latest per-dimension scores from `score_history[-1].dimensions`.
- Score history area chart (Recharts) deduplicated per calendar day ([hooks/useDashboard.js:91-104](hooks/useDashboard.js#L91-L104)).
- Monday brief card: latest brief, "is new" indicator, opens to full text (auto-marks `was_opened: true` on view).
- Constitution plant SVG grows from seed → sprout → plant → tree based on `constitutionProgress.answered` ([components/ConstitutionPlant.js](components/ConstitutionPlant.js)).
- **Tools row** — Content Idea, Voice Check, Trend Fit cards. Each surfaces its constitution origin (see §5.6 below).
- Sidebar nav with brand name, industry badge, user email ([components/Sidebar.js](components/Sidebar.js)).

**Routing guard** — if `profile.current_roadmap` and `localStorage.brandshift_roadmap` are both missing, redirects to `/results` (where user can generate a roadmap).

### 5.5 Brand Constitution (Brand Bible)
- 4-step wizard with grouped questions: Brand Identity, Customer, Voice, Edge. ([app/(dashboard)/constitution/page.js](app/(dashboard)/constitution/page.js))
- Each step has 3 questions (textarea / tag-input).
- `/api/constitution/save` upserts via `c_*`-prefixed columns; `/api/constitution/load` returns existing answers and resumes at `c_current_step`. ([app/api/constitution/save/route.js](app/api/constitution/save/route.js))
- `/api/constitution/generate` calls Claude to produce a 9-section Brand Bible (Who We Are, Who We Are Not, Who We Serve, How We Speak, …) saved to `c_bible_content`, with up to 3 retry attempts. ([app/api/constitution/generate/route.js](app/api/constitution/generate/route.js))
- Completed bible renders inline with formatted section headers, post bullets, and Download-as-PDF / Copy text / Edit answers buttons.

### 5.6 Tools

Every tool surfaces the constitution answer that informed it, making the connection visible.

- **Voice Check** — rewrites user-supplied copy to match the brand's voice signature; 10-per-day rate limit tracked via `voice_check_date` + `voice_check_count`. ([app/api/tools/voice-check/route.js](app/api/tools/voice-check/route.js))
  - **Constitution-locked**: if `constitutionProgress.answered < 3`, the card is overlaid with a `rgba(8,8,14,0.7)` blurred lock (🔒 + "Complete 3 constitution questions to unlock Voice Check" + violet "Complete now →" button → `/constitution`).
  - When unlocked and a rewrite is shown, the rewritten-copy panel includes italic footer: "Avoided: {first 3 of `c_off_brand_words`}".

- **Content Idea** — single specific content idea (format / theme / hook / why) tied to current roadmap theme and Indian seasonal calendar. Cached on `latest_content_idea`. ([app/api/tools/content-idea/route.js](app/api/tools/content-idea/route.js))
  - After the idea, footer divider shows "Tailored to your personality: {first 3 of `c_personality_words`}".
  - If `c_personality_words` is empty, the footer is amber-coloured: "↑ Complete your Brand Constitution for personalised ideas".

- **Trend Fit** — 5 current Indian trends rated `use / avoid / test` for this specific brand. Cached on `latest_trends` for 7 days. ([app/api/tools/trend-fit/route.js](app/api/tools/trend-fit/route.js))
  - Each expanded trend row appends italic "Based on your customer: '{first 60 chars of `c_best_customer`}…'".

Immutable per-run snapshot for historical recall. Columns mirror the score request body: `brand_name`, `industry`, `brand_age`, `target_audience`, `website_url`, `instagram_handle`, `challenge`, `scraped_homepage/about/blog/instagram/comp1/comp2`, `score_json` (jsonb), `overall_score`, `rebrand_urgency`, `data_confidence`, `created_at`. - `id`, `account_id` (FK → accounts), `brand_profile_id` (FK → brand_profiles), `role` ('owner'), `is_active` bool. Composite key `(account_id, brand_profile_id)`.

## 8. Authentication & Authorization

### Stack
- Supabase Auth — sessions via httpOnly cookies (`@supabase/ssr`)
- Three client variants used together:
  - **Admin** ([lib/supabase.js:5-9](lib/supabase.js#L5-L9)) — `SUPABASE_SERVICE_KEY`, server-only, bypasses RLS. Used in every API route that mutates data.
  - **Server SSR** ([lib/supabase.js:17-29](lib/supabase.js#L17-L29)) — anon key bound to incoming cookies, used to `getUser()` and validate the session in auth-aware routes.
  - **Browser** ([lib/supabase-browser.js](lib/supabase-browser.js)) — anon key, used inside `useAuth` and client pages.

### Sign-in methods
- Email + password ([app/login/page.js:47-54](app/login/page.js#L47-L54))
- Magic link via `signInWithOtp` ([app/login/page.js:56-67](app/login/page.js#L56-L67))
- Google OAuth ([app/login/page.js:38-45](app/login/page.js#L38-L45))
- LinkedIn OIDC — uses `provider: 'linkedin_oidc'` with `scopes: 'openid profile email'` (requires LinkedIn Developer Console app + Supabase provider configured)

### Authorization model
- **Route protection** is enforced by [middleware.js](middleware.js): the matcher excludes `_next` static assets, images, favicon, and `/api`. Protected paths (`/dashboard`, `/roadmap`, `/preflight`, `/constitution`, `/outreach`, `/reports`, `/settings`) redirect unauthenticated traffic to `/login?redirect=…`. Authenticated users hitting `/`, `/login`, or `/signup` are redirected to `/dashboard`. The middleware ignores API routes by design — API auth is handled per-route.
- **Brand ownership** is enforced server-side via `owner_user_id` checks (when present). The brand-claim flow in `/auth/callback` and `/api/auth/associate-brand` only attaches *unowned* profiles to a user, then writes to `accounts.primary_brand`. The `useDashboard` hook trusts whatever `account.primary_brand` says.
- **Plan gating** — `useAuth` exposes `isPaid` (`plan in ['starter','agency']`) and `isAgency`. Currently informational; no route hard-gates on plan in code, but the settings page surfaces it.

### What's NOT enforced
- API routes mutate via `supabaseAdmin` (service key, bypasses RLS) without re-checking `user.id === profile.owner_user_id`. A determined caller knowing a brand name could read/write that brand. This is acceptable for current single-user flows but should be tightened before agency multi-tenant rollout.

### Auth-flow landing-page flash fix (commit `ebd052d`)

User reported: "as soon as I click on login and choose an account, I'm still being redirected to the landing page and then in a few seconds I'm redirected to the dashboard." Three layered fixes:

1. **[middleware.js](middleware.js)** — Authenticated users hitting `/` are now redirected to `/dashboard` server-side (joined the existing `/login` and `/signup` redirect list). Runs before HTML is rendered, so it's the fastest path.
2. **[app/page.js](app/page.js)** — Synchronous first-render guard: if the URL has an OAuth hash (`access_token`/`refresh_token`/`error_description`), a PKCE `?code=` query param, or any live `sb-*-auth-token` cookie, the page renders a logo + spinner splash instead of the landing UI. Covers the case where Supabase OAuth falls back to Site URL (`/`) instead of `/auth/callback`. Stale cookies with no real session flip back to the landing page after `getSession()` resolves.
3. **Single-call post-auth redirect** — The landing-page `useEffect` now makes only `/api/auth/account` (was account + profile) before `window.location.replace('/dashboard')`. The dashboard's own `current_roadmap` guard handles further routing. The previous two-call version was the main cause of the multi-second flash.

**Supabase Dashboard config reminder**: add `https://<vercel-domain>/auth/callback` and `http://localhost:3000/auth/callback` to Authentication → URL Configuration → Redirect URLs. Without them, OAuth falls back to Site URL (`/`) and round-trips through the splash unnecessarily — the code handles it gracefully but it's wasted work.

## 12. Deployment

### Where
- **Vercel** (current: `brand-shift-tpea.vercel.app`, target domain: `brandshift.in`)
- **Supabase** project `fgujotnczwejuortvxne` — single shared instance for prod
- **GitHub** repo: `goyal14gautam-max/BrandShift`, main branch auto-deploys

### Build
- Auto-detected as Next.js. `npm run build` runs `next build`. No special build env required beyond the runtime vars listed in §10.
- [next.config.js](next.config.js) externalises `apify-client`, `proxy-agent`, `got-scraping`, `node-vibrant` from the webpack server bundle (they use dynamic `require()` patterns Webpack can't statically resolve).

### Runtime limits
- Default API function `maxDuration`: **60s** (Vercel free-tier max for serverless is 300s)
- Overrides:
  - `/api/monday-brief/cron` → 300s ([vercel.json](vercel.json))
  - `/api/scrape` → 300s (`export const maxDuration = 300` in the route file)
  - `/api/score` → 60s
  - Various tool routes explicitly set `maxDuration = 60` or `30`

### Cron
- Single cron: `0 18 * * 0` → `/api/monday-brief/cron`. Translates to **Sunday 18:00 UTC** (Monday 23:30 IST). Bearer-token-protected via `CRON_SECRET`.

### Deploy procedure
Per [README.md](README.md):
1. Push to GitHub `main` → Vercel auto-deploys
2. Env vars are managed in the Vercel dashboard under Settings → Environment Variables
3. After adding a new env var, redeploy from Deployments tab (Vercel doesn't pick up new vars on existing builds)
4. Custom domain configured via Vercel → Domains; A/CNAME records on the registrar (24-48h propagation)

### Database migrations
- No migrations framework. Schema is evolved via raw SQL in the Supabase SQL editor. Recent column additions documented in the conversation history (e.g. all `c_*` constitution columns, `linkedin_url`, `scraped_linkedin`). When adding a column, run `ALTER TABLE … ADD COLUMN IF NOT EXISTS …` in Supabase **before** deploying code that writes to it — saves will silently fail otherwise because the API routes catch and log save errors without surfacing them.

### Local development
```bash
npm install
# populate .env.local with the variables in §10
npm run dev   # http://localhost:3000
```

No test command. `npm run lint` runs Next.js's default ESLint config.
